## 3. 代码关键机制（接手改代码前必须知道）

### 3.1 抓取主路径（`scripts/distributed_worker.py`）
- Redis 租约队列（claim/ack/nack/release，死信队列），`LeaseWorker` 管多个 `_ChromeGroup`，每组一个 Chromium 进程绑一条代理，若干标签页。
- 过 CF：第一页用 scrapling `StealthySession`（Patchright Chromium）渲染，`solve_cloudflare=True` 自动等/点 Turnstile；拿到 `cf_clearance` 后 `box.warm=True`，后续页走 `fetch_document`（同浏览器上下文的 HTTP 请求，不渲染）。会话每 `TPS_SESSION_RECYCLE=120` 页重建。
- 限流三路：
  - 验证码/挑战页 → `[fp_restart]` 同 IP 刷指纹，连续 2 次换代理，本组休 `TPS_FP_REST_SEC=45`。
  - 429 且有独立备用出口 → `[lane_switch]` 换道，热身 `TPS_LANE_WARM_SEC=15`，全局不停。
  - 429 且是动态网关（host 含 cloudbypass/gw-res）→ 账号级暂停 20/40/60 秒（`ACCOUNT_PAUSE_STEPS_SEC`）。**客户现在就是这种**，所以吞吐上限由穿云账号决定，不是代码。
- 自适应领取间隔：基线 `TPS_CLAIM_GAP_SEC` + 近期限流比例×12 + 抖动，封顶 18 秒。

### 3.2 自研过 CF 插件（`scripts/cf_solver.py`，本轮新增）
- `TPS_OWN_CF=1` 时**不开浏览器**：向 `TPS_CF_SOLVER` 要凭证，用 curl_cffi 在同一代理上发协议请求，TLS 目标按凭证 UA 的 Chrome 主版本自动挑。
- `TPS_CF_SOLVER` 三种写法：`module:callable` / `http://host/path`（POST JSON）/ `cmd:exe`（stdin→stdout JSON）。
- 请求 `{url, proxy, user_agent|null, timeout}`；响应 `{cookies, user_agent, html?, ttl?}`。
- 凭证被拒重解一次，再被拒按验证码上报走 fp_restart；求解器挂了同样按验证码处理（任务 release，不进死信）。
- `TPS_OWN_CF=1` 但没配 `TPS_CF_SOLVER` → worker 启动期直接报错退出。
- **当前客户机 `TPS_OWN_CF=0`**，这条路径还没在客户机真跑过。

### 3.3 上游代理拉取（`scripts/proxy_pool.py`）
- `PROXY_API_URL` 启动拉取 + 每 `PROXY_API_REFRESH_SEC` 热合并，缓存 `data/proxy_api_cache.txt`。客户没有这种 API，当前未使用。

### 3.4 Windows 包完整性
- `bundle-manifest.json` 记录每个文件 sha256/size；`Test-FullBundle.ps1` 校验，**不在清单里的文件直接报错**，所以新增文件必须加清单条目。
- `Repair-RuntimeBinding.ps1 -Confirm:$false` 重写 `runtime\runtime-manifest.json`，换过任何 app 文件后必须跑。
- `Common.ps1` 的 `$script:AllowedRuntimeKeys` 是 runtime.env 键白名单，新键必须先加白名单。
- PS 5.1 坑：ps1 文件无 BOM 时不能含任何非 ASCII 字符；`Test-FullBundle.ps1` 没有 `-Confirm` 参数；Move-Item 不能覆盖已有文件。

## 5. 一路踩过的坑（都已解决）

1. 客户机 Cline 在 VS Code 普通权限下跑，`D:\truepeoplesearch` 有保护 ACL → 读不了文件。**解法：VS Code 以管理员身份重开**（另开管理员 PowerShell 窗口没用）。
2. Docker Desktop 没启动 → Start-Stack 连不上引擎。用户手动启动后解决。
3. `D:\TruePeopleSearch\data\mysql\mysql.sock` 是 reparse point，触发 Start-Stack 的持久存储检查失败。授权 Cline 停 MySQL 后删了它，Start-Stack 通过。
4. 客户机 `docker-compose.yml` 是旧版（mysqld socket 在 datadir），补发了新版（`--socket=/tmp/mysql.sock`），`docker inspect` 确认 Cmd 已生效。
5. 早期：`Common.ps1` 一行中文注释 + 无 BOM 导致 PS 5.1 解析失败；`Test-FullBundle` 不认 `-Confirm`；runtime.env 新键不在白名单；并发上限 1–8 太低；客户机没有 git → 改成 `Invoke-WebRequest` 下 zip。全部已修。
6. 代理地址一度被用户贴进对话多次，Cline 拒绝使用对话里的凭据。最终方案：用户自己用记事本写进 runtime.env，脚本只检查键是否存在。
